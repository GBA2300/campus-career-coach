# 10 证据链与包装红线（防面试露馅）

## 一、核心原则

简历上的每一句话，都是面试时**必须能兑现的提款单**。兑现不了，就是在透支信用——一旦被追问住，前面所有真实的经历都会被怀疑。

判断一条 bullet 是否安全，只看一个标准：**能不能被追问三层还讲得出来。**

## 二、三层追问法（每条 bullet 都要过）

| 层级 | 面试官会问 | 你必须答得出 |
|---|---|---|
| 第 1 层 | 做了什么？结果是什么？ | 一句话说清目标与结果 |
| 第 2 层 | 具体怎么做的？为什么选这个方案？最难的是什么？ | 3 个具体动作 + 一个真实困难 + 你的解法 |
| 第 3 层 | 这个数字怎么算出来的？谁可以证明？如果重来改哪里？ | 数据来源口径 + 可验证的人/物 + 一条真诚反思 |

**任一层答不出 → 该条不安全**，处理方式二选一：回素材库补细节，或从简历删掉。

## 三、证据的四种类型（够一种即可，越多越稳）

1. **数据证据**：能说清口径与来源（"粉丝数来自公众号后台，取 6 月 30 日快照"）。
2. **物证**：报告、原型、代码、推文、截图、表格、作品集链接 **可当场打开**。
3. **人证**：leader / 导师 / 队友，面试前打好招呼。
4. **过程证据**：能讲清中间的决策与失败（只有真做过的人才讲得出过程）。

## 四、包装红线（这些绝不能做）

| 行为 | 后果 |
|---|---|
| 把"参与"写成"主导/负责" | 追问分工即穿帮 |
| 数字注水（500 说成 5000） | 追问口径即穿帮，且属诚信问题 |
| 把没做过的项目/实习写进简历 | 背景调查（尤其大厂/银行/国企）大概率查出 |
| 把团队成果完全算在自己头上 | 追问"你个人做了哪部分"即穿帮 |
| 编造公司名或实习时间 | 社保/背调/入职材料对不上 |
| 技能造假（写"精通 Python"但写不出代码） | 笔试或现场 coding 直接暴露 |

## 五、允许的"包装"边界

**可以做（表达优化）**：
- 用更强的动词准确描述你确实做过的事（"参与"→"独立完成 XX 模块"）。
- 用更合适的量化方式呈现真实结果（"做了很多次"→"累计完成 23 次"）。
- 把零散的同类经历合并成一个更有说服力的项目（但时间、角色必须真实）。
- 调整叙述重点，突出与目标岗位相关的部分。

**不可以做（事实篡改）**：改变角色、改变归属、改变数量级、凭空增加。

**一句话判据**：这句话如果被面试官用另一种方式再问一遍，我答的答案会不会变？会变 = 越界。

## 六、自检 SOP（简历定稿后、面试前一天各做一次）

1. 运行 `scripts/evidence_check.py` 生成/更新 `求职档案/证据链.md`。
2. 逐条自述：对每一条 bullet，**大声说 30 秒**，讲不顺的标记出来。
3. 互相追问：教练（AI）对标记的条目连问三层，答不出就回炉。
4. 覆盖率 < 70% 不要投递；< 90% 不要面第一志愿公司。
5. 面试前一天，把证据链里的物证（作品链接、报告、代码）**全部点开确认可访问**。

## 七、`求职档案/证据链.md` 模板

```markdown
# 证据链校验（更新于 YYYY-MM-DD）

覆盖率：X / Y 条（Z%）

| # | 简历条目 | 素材出处（素材库第几条） | 可追问层级 | 物证 | 状态 |
|---|---|---|---|---|---|
| 1 | 独立运营公众号，3个月粉丝800→5200 | 素材库 #3 | 3 层 ✓ | 后台截图 | 安全 |
| 2 | 用 Python 自动化周报处理 | 素材库 #7 | 2 层 △ | 脚本文件 | 需补第3层 |
| 3 | 统筹 12 人团队 | ⚠️ 素材库无对应记录 | 1 层 | 无 | **删除或补素材** |

## 待处理
- [ ] 第 2 条：补上"为什么选 pandas、数据量多大、节省多少时间"的细节
- [ ] 第 3 条：素材库里查不到，要么补素材，要么从简历删掉
```

## 八、对用户的说法（照这个语气说）

不要说教。用这句：

> 这条我帮你写得很好看，但我得提醒你：面试官一定会问"这个 550% 是怎么算出来的"。你现在的素材里没有这个细节。**要么我们现在把它补上，要么把它改回保守版本**——吹爆一个点，会让 HR 怀疑你整份简历。你选哪个？
